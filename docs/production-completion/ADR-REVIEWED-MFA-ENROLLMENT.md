# Initial staff MFA enrollment and first administrator

Privileged phone OTP is AAL1. Ordinary step-up requires an already bound MFA identity. An unrelated MFA account plus a staff phone OTP must never self-enroll a privileged factor.

Schema49 adds a separate, time-limited enrollment request. The owned active base session must be less than ten minutes old. The server verifies the OIDC signature, exact issuer/audience/authorized party, request nonce, explicit MFA assurance, and provider authentication time within five minutes. Client-posted subjects, emails or assurance claims are never accepted. Only the digest of the ID token is persisted. State, PKCE, nonce, mode and session binding survive only the signed ten-minute browser flow. OIDC state-cookie paths derive from the externally registered callback, including the VPS `/api` prefix.

Enrollment leaves the staff session AAL1. An independent platform administrator with a recent AAL2 session verifies the exact corporate issuer and subject through a trusted channel and records a decision note. Tenant managers cannot approve global identity factors. Database triggers enforce actor/session/expiry/self-approval/target eligibility, preserve request evidence and atomically bind an approved identity and append its security event. Identical decision retries are stable; conflicting decisions and replacement of an existing factor fail closed. The staff member must then repeat ordinary MFA sign-in. Approval does not issue or upgrade a session.

Bindings now include issuer. Existing unscoped bindings remain quarantined rather than being guessed from environment variables. An issuer migration, lost factor, revoked binding or legacy reassignment needs a separately reviewed recovery procedure; initial enrollment cannot replace it. Verified email never merges accounts. Database operators retain their inherent administrative power; separate least-privilege database credentials and audited access remain an operational launch requirement.

For an empty installation, an owner first signs in using genuine provider MFA, creating a pending, issuer-scoped identity. The offline `packages/database/scripts/bootstrap-platform-admin.mjs --approve-initial-platform-admin` command requires the exact pending user/issuer/subject, a recent genuine OIDC AAL2 session, and an independent owner review note. It refuses to run once any platform administrator assignment exists, activates only that owner, appends an audit event, and revokes pre-approval sessions. It creates no synthetic MFA proof. The owner signs in again before reviewing staff requests. No public bootstrap endpoint exists.

The user status page and administrator review page have English/Arabic copy and use the shared RTL locale provider. Normal privileged workspace guards remain unchanged.

The request-token checks follow [OpenID Connect Core ID Token validation](https://openid.net/specs/openid-connect-core-1_0.html#IDTokenValidation). Local certification uses an explicitly synthetic loopback IdP with signed RS256 tokens and a disposable PostgreSQL database; it proves software behavior, not real-provider MFA configuration or owner identity.
