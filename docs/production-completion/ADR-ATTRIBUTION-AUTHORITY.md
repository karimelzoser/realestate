# Buyer attribution and historical deal authority

Shared buyer identity is tenant-scoped and immutable. Current source/company/agent/revision live in buyer_project_attributions keyed by buyer profile and project; joining or transferring one project cannot change another project. Project registration is insert-or-read, never a transfer or lifecycle reactivation. An active buyer may safely retry their own DIRECT registration and receive the existing profile ID without changing a recorded broker. A staff/broker retry with different attribution returns conflict and must use the approved transfer workflow. Existing-profile retries emit no false upsert event.

Attribution review is a distinct capability for active project/tenant Managers and Operations Directors. Sales/Reception/Broker Managers may manage permitted prospects but cannot approve ownership transfers. SQL review also checks actor membership, project/tenant lifecycle, target organization/link/company/agent and effective agreement/project access.

Migration48 adds monotonic attribution revisions. New request evidence is frozen to the source/revision; reviewed transfer evidence is immutable. Approved history applies only its project attribution projection through a nested database trigger. Generic SQL updates and forged session flags cannot alter attribution; historical events cannot be consumed twice. Legacy history remains unchanged, with an explicit migration baseline for the current projection.

Reservation freezes source/company/agent/revision at sale creation. Commission ownership, transaction/finance access and deal exports use that snapshot; a later prospect transfer cannot move an existing deal or agent commission. Legacy reservations are backfilled only from existing immutable commission-case evidence; otherwise attribution remains unrecorded, not guessed from today's mutable buyer profile. Such rows require explicit historical evidence/remediation before brokerage assignment.

Project buyer attribution is the current prospect/EOI/queue authority; the shared profile's original/default fields are not current deal authority. Migration prefers existing project-specific approved transfer/history evidence for known current scopes and records an explicit baseline; historical deal ownership still comes only from existing commission cases. Reservation evidence is the historical sale authority. Normal inactive/suspended role and agreement controls still apply. No generic broker-clearing or retrospective commission correction route is introduced by this slice; owner-approved policy for those exceptions remains separate.

Certification must cover buyer self-retry, other-broker takeover rejection, inactive lifecycle retry, one concurrent create/event, direct SQL/session-flag bypass, stale source/revision, explicit review capability, inactive reviewer/target, terminal decision retries, transfer races, frozen historical deal access/commission/export, and schema47 upgrade without inventing legacy ownership.
